# Experimental persisted .NET runtime binding

`ApsDda.Runtime` implements selected APS-DDA v0.1 action-lifecycle requirements on .NET 10. It uses the unchanged original schema through `ApsDda.Core`, not a competing reduced artifact shape. New source development was AI-assisted. This is not full syntactic/behavioral/semantic conformance, a certified security boundary, a production OAuth service, or evidence that a live insurer can replace its analytical platform.

## Actual persistence and transaction boundaries

`SqliteRuntimeStore` opens a file-backed SQLite database with WAL, `synchronous=FULL`, a 30-second busy timeout and immediate write transactions. Connections are short-lived and not pooled. Its versioned local schema retains original artifacts with their detached signature envelopes, content-addressed protected evidence values, authenticated authority admissions, authority-use bindings, workflow steps and normalized payloads, original invocation/receipt references, source resource state, source operation results, current policy pins, cancellation intent and local artifact/issuer/key revocations.

Artifact type/ID/version is immutable: different bytes under the same identity conflict. References resolve only retained exact type/ID/version/digest. Evidence values use `urn:aps-dda:value:sha256:<hex>` where the digest is SHA-256 of JCS of the complete protected JSON object. They are never fetched from a URL. Applications must restrict store access: its retention, provisioning, resource seeding, policy changes and revocation methods are **trusted administrator/in-process APIs**, not public endpoints. This is not encrypted SQLite and has no automatic retention/deletion or archival service.

An authority service transaction consumes the Approval or policy-grant identity to one correlation UUID, exact plan digest and ordered permitted-step set. It commits before dispatch. Consumption is distinct from the source transaction and does not promise that an effect will follow. A repeat of the same authority binding returns the existing workflow; a different binding is refused. New runtime/store objects over the same database retain those rows and original invocations.

`SqliteSourceAdapter` validates current controls, reads the expected local version and applies its reviewed `ILocalSourceCommand`. It updates the resource and inserts the original operation, signed receipt, protected postcondition and signed evidence in **one** local SQLite transaction. It validates time, policy, authority and local revocation again before committing. A stale version or source-owned capacity guard rolls back without a new effect. The tests include an operation-insertion fault after the resource update and verify the update and receipt roll back together.

The reference stores for different logical sources may share a test database, but each source action is its own transaction; no transaction spans two source commands. Two independently signed sources are tested for successful capacity reservation plus internal notification-draft preparation, and for a second-source stale failure that preserves the first source's effect. Real external adapters must provide their own local operation/effect durability inside their source boundary. Merely wrapping an external API with this coordinator cannot provide that guarantee.

## Identity and source authorization

`PrincipalDirectory.Register` provisions immutable `AuthenticatedPrincipal` handles from administrator configuration. `ResolveAuthenticated` is called **after** a host has authenticated an identity. It is not a login operation, and an identity string supplied by a request must never be resolved as though authenticated. The runtime verifies that the handle is the currently registered object with the required role; an old, revoked or foreign-directory handle fails.

Incoming original `ExecutionContext` is a claim to compare, not a trusted caller. Its tenant, subject, workload, executor, purpose, classification and residency must match the authenticated principal and configured permissions. Correlation remains the original durable workflow UUID. Delegation is explicitly unsupported and refused rather than assumed valid. Source dispatch independently intersects configured subjects, workloads, roles, purposes, exact resources, capability digests, audiences, classification and residency with principal permissions. Source contracts and products must be tenant-trusted and exact-pinned; receipt/evidence verification requires the actual configured source issuer.

An authenticated independent `Approver` creates or admits an Approval signed by the configured authority-service signer. Its `approverId`, complete context, exact plan, policy record, allowed step IDs, effect summary, issue time, expiry and single-use condition are checked. Admission retains the authenticated identity separately from the artifact. Revoking that principal stops later effects. The executor cannot substitute itself as approver. The effect summary is deterministically derived from approved steps and commitments. A real approval UI must additionally render **the complete retained normalized payload** obtained by an authorized server through `Store.GetPayload`, not just a digest or a redacted summary. This library has no approval UI or step-up authentication provider.

`PolicyDecision` with `allow` remains evidence, never a grant. `EligibilityPolicy` is a deliberately small deterministic policy: an eligible DecisionSpec yields `allow` or `allow-with-human-approval` depending on its pinned configuration; other eligibility yields denial. It is not an insurance/actuarial decision model or an entitlement engine. Deployments supply a reviewed `IRuntimePolicy` when different business evaluation is required.

A policy grant is accepted only from an authenticated `PolicyGranter` admission, for the exact plan, and where both source configuration and pinned capability permit it, do not require a human, and declare **low** risk. This binding supports one exact capability/resource/audience boundary per grant and canonical positive integer quantity strings. The complete planned quantity must not exceed either the granted maximum or source maximum. A source-owned rolling one-minute operation rate is evaluated inside the effect transaction. Amount/money grants, delegation grants and broader wildcard boundaries are refused. The status URI must be the configured authority issuer plus `/status`; it identifies this local durable status source and is not fetched. Remote status distribution and production revocation propagation are not implemented.

## Evidence and policy coherence

`EvidenceRule` pins an actual DataProduct reference, expected issuer, full exact semantic-reference array, maximum observation age, accepted quality state and a deterministic protected-value validator. Sources name the rules they require. Evidence is original-schema, signed, retained and context-bound. Its items must use a reviewed pinned product, source issuer, exact semantics, permitted purpose/classification/residency, current observation time, accepted quality, and `live` cache status. Protected values must actually exist and match their content-addressed digest, and the source-configured domain validator must succeed. Unknown rules, mismatched units or regions, stale/future observations, unknown extensions and unsupported coordinated-snapshot claims fail closed.

The selected runtime accepts observational evidence. It does not implement arbitrary identity mappings, semantic equivalence, historical corrections, distributed snapshots, read query budgets or source truth guarantees. Domain authors must validate grain, entity/time/currency/calendar/model meaning explicitly in their reviewed value validators and policy; a signature only authenticates bytes. The source's own mutable resource version is checked atomically with its effect. Any required external hard invariant, or undeclared capability invariant that lacks an enforcing implementation, is refused as `UNSUPPORTED_PROFILE`. Fresh reads do not turn an external condition into a protected invariant.

A configured policy reference is explicitly provisioned with `Store.SetCurrentPolicy`; restarting a runtime does **not** reset it. The plan, DecisionSpec and PolicyDecision must have identical complete original contexts and the exact configured policy reference. The declared policy version, outcome, obligations and decision digest must match actual deterministic evaluation, and evaluation age is checked at dispatch. Decision action eligibility must be `eligible`.

The external policy-record digest convention is explicitly experimental: `RuntimeDigests.PolicyDecision` computes `sha256:hex(SHA256(JCS({profile, decisionRef, policyRef, outcome, obligations})))`, where `profile` is `aps-dda.experimental/policy-evaluation/1`, `policyRef` is the exact external rule reference, and obligations retain order. `EligibilityPolicy`'s external rule bytes are exactly `{profile:"aps-dda.experimental/eligibility-policy/1", version, requireHumanApproval}` under the same JCS SHA-256 convention. `ArtifactFactory.SchemaReference` and deterministic method parameters also explicitly adopt JCS SHA-256. These are publisher-defined external resource conventions, not amendments to the original standard's artifact digest.

## Idempotency, ambiguous replies and verified results

A source operation key is `(tenant, source issuer, idempotency domain, idempotency key)`. Its fingerprint uses Core's documented `aps-dda.experimental/invocation-fingerprint/1` convention. Duplicate same key and fingerprint returns the **original** operation and signed receipt with no further effect; a changed fingerprint yields `IDEMPOTENCY_KEY_REUSE_CONFLICT`. Source lookup remains an authenticated read, but can reconcile a past committed operation after the original authority expires; expiry cannot rewrite a historical source effect. It does not authorize a new effect.

Before transport the runtime durably retains the original CommandInvocation and marks the step `UNKNOWN`. A worker crash, timeout, lost reply, SQLite I/O/commit ambiguity or bad response remains unknown, not a clean failure. `ExecuteNext` detects that state and calls `Lookup` before any possible resend. This deliberately conservative subset **never automatically resends**, even when lookup returns not-found. An absent or ambiguous original operation remains `UNKNOWN_OUTCOME` with the plan's manual owner. It never mints a new correlation ID or idempotency key. After a known source refusal, the workflow is `REJECTED` if there was no prior effect; there is no invented completed source operation or success receipt.

Completion verifies both native source signatures and exact invocation/receipt/postcondition links. The original durable source operation must match the returned receipt and evidence. Protected postconditions contain actual target, version, before/after state, original invocation reference and operation ID. Their query commitment is JCS SHA-256 of `{profile:"aps-dda.experimental/source-postcondition/1", target, operationId, invocationRef}`. The verifier compares version to the source-enforced expected version plus one, matches source product/semantics/time/quality, and reruns the source-local command against the retained before-state to check the actual after-state. A signed but wrong-version receipt, bad signature, wrong source issuer or failed postcondition cannot complete the workflow. Historical postconditions remain valid records even if the current resource later changes.

`SourceRefusedException` is reserved for a source-enforced **known pre-commit** refusal. External adapters must not label a timeout, unverifiable reply or potentially committed operation with this exception. All other adapter/verification failures remain unknown. Fault injection exists only in tests via in-process decorators and SQLite triggers; there are no public fault/reset or arbitrary SQL/code endpoints.

## Partial completion and cancellation

This subset implements explicit non-compensability with an accountable manual owner, not generated compensation or a fake global rollback. Every step's recovery mode and owner must match its exact source capability. A known second-step refusal after a verified first effect produces `MANUAL_RESOLUTION_REQUIRED` and retains the first receipt/state change. Revocation or expiry before a future step stops that step, not the historical effect.

Cancellation durably stops pending steps and is rechecked at a source before any new commit. A known no-effect pre-dispatch cancellation yields `CANCELED`. A cancellation after an effect yields manual resolution. Cancellation while an invocation is ambiguous stays `UNKNOWN_OUTCOME` until the original operation is reconciled; a recovered effect is not described as undone or cleanly canceled. Completed original source receipts are preserved rather than rewritten.

## Developer recipe and actual verification

Use `ArtifactFactory` to construct original-schema Context, DataProduct, ProcessCapability, EvidenceBundle, DecisionSpec, PolicyDecision, ExecutionPlan/steps, Approval, Authority and CommandInvocation with actual digests. Generate/load P-256 signing keys at runtime and independently configure `TrustedParticipant` entries and exact contract pins before retaining artifacts. Build capability/product before provisioning caller capability/resource/audience permissions. Configure `EvidenceRule` meaning checks and `SourceRegistration`, create `WorkflowRuntime` and `SqliteSourceAdapter`, then `RegisterSource`. Retain the signed evidence/decision/policy under their configured trust requirements. Supply normalized effect payloads separately to `Submit`; they are not invented fields in closed original plan bodies. `Approve` plus `Authorize`, or `ArtifactFactory.PolicyGrant` plus authenticated `AdmitAuthority` and `Authorize`, precedes `ExecuteAll`. Consult [the exact API contract](../API_CONTRACT.md) and [the executable test harness](../tests/ApsDda.Runtime.Tests/Harness.cs) for full constructor signatures and generation order.

`ReserveCapacityCommand` mutates synthetic source-owned available/reserved internal units. `PrepareNotificationDraftCommand` increments a synthetic internal draft count; it sends no message and makes no customer, payment, fraud, claims or entitlement decision. Custom `ILocalSourceCommand` implementations are reviewed server code, never client executable payloads. `ISourceAdapter` supplies source-owned measure, invoke, lookup and postcondition verification boundaries for later integrations.

Run from the repository with .NET SDK 10.0.403 on Linux or Windows:

```sh
dotnet restore ApsDda.sln --locked-mode
dotnet build ApsDda.sln -c Release --no-restore
dotnet test tests/ApsDda.Runtime.Tests/ApsDda.Runtime.Tests.csproj -c Release --no-build
```

Microsoft.Data.Sqlite 10.0.0 is pinned, with an explicit SQLitePCLRaw.lib.e_sqlite3 3.53.3 native override. The initial transitive 2.1.11 restore reported GHSA-2m69-gcr7-jv3q; the patched native dependency was verified rather than suppressing NuGet Audit, and the tests execute `sqlite_version()` to require 3.53.3. Lockfiles retain transitive hashes. Native SQLite package metadata is at [NuGet](https://www.nuget.org/packages/SQLitePCLRaw.lib.e_sqlite3/3.53.3); advisory metadata is at [GitHub Advisory Database](https://github.com/advisories/GHSA-2m69-gcr7-jv3q).

Actual runtime test results and build status are recorded separately in the API contract after execution. This is developer-run local persistence, not a deployed persistent service. Private-key persistence/rotation, production identity-provider integration, OAuth/mTLS/HTTPS transport, encryption/retention, durable principal/trust provisioning, remote revocation distribution, automated compensation, source API interoperability, outbox/work queues, migration management and performance/load testing remain unimplemented. HTTPS and an appropriate authenticated provider are required for production adapters; no production-readiness or full conformance claim is made.

The final selected-profile runner also requires the DecisionSpec evidence set to equal the exact union of plan-step evidence references. Each source revalidates that **complete decision evidence set** at dispatch and immediately before its commit, including evidence used by other steps, while also requiring its configured EvidenceRules. Final verification on 3 November 2026 passed 85 real runtime tests and 130 unchanged Core tests with no failures/skips; locked restore/Release build had no warnings/errors. An outside-checkout NuGet consumer completed a signed original-schema, human-approved SQLite effect and durable reopen. These are local reference tests, not external certification or live-source pilot results.
